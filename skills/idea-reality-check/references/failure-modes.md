# Common failure modes and the test for each

Pick the 3 most likely for the idea at hand. A failure mode without a test is a worry, not a plan.

| Failure mode | Sign you are in it | Cheapest test |
|---|---|---|
| Nobody pays for this problem | they agree it hurts but spend nothing on it now | ask 5 buyers what they spent on it last quarter |
| Wrong buyer | the user loves it, the person with the budget does not care | ask who signs off and talk to that person |
| Do nothing wins | the workaround is annoying but free | price the workaround in their hours and refunds; ask for a pre-order anyway |
| Cannot reach them | no list, no group, no query | find 20 named buyers in one afternoon; if you cannot, the channel is the problem |
| Access or trust | the service needs their data, store, inbox or money | ask 5 buyers for the access now, before the offer exists |
| One and done | the fix lasts, so nobody renews | ask how often the problem comes back; design the monthly part or price it as a project |
| Delivery does not scale | each job takes a full day of your time | count the hours on the first 3 jobs; set the capacity and price from that |
| A platform removes the pain | the tool they use could add this as a feature | check the tool's public roadmap and forums; sell the outcome and the work, not the feature |
| Price too low to matter | the buyer would pay more than the price you named | run a Gabor-Granger or ask for a pre-order at a higher price |
| Seller cannot deliver | the seller has never done this for a client | do it once for free, with a written before and after |

## Timing questions

- Why would they buy this month and not next year? Name the trigger (a season, a law, a new channel, a bad sale).
- What has to be true in the world for this to work, and is it true now?

## Effort against reward

Write both in plain words. "3 weeks to set up; 5 shops at the monthly fee covers the month" is enough. If the reward
needs a number you do not have, say so; do not invent one.
